# AGENTS.md — Personal Website

## Project identity

This repository contains my personal and professional
website.

The website should communicate my identity as an academic,
professor and researcher in astronomy.

Its purpose is to present:

- Professional biography.
- Research interests.
- Scientific projects.
- Publications.
- Collaborations.
- Academic activities.
- Contact information.

Inspect the existing website before making assumptions
about its structure or content.

## Design philosophy

Aim for a professional, modern and elegant academic website.

Priorities:

- Clean and minimalist design.
- Strong typography.
- Excellent readability.
- Intuitive navigation.
- Responsive layouts.
- Fast loading.
- Consistent visual identity.

Avoid generic corporate templates and unnecessary animations.

The design should feel personal, credible and scientifically
oriented.

## Content

Preserve the accuracy of all academic information.

Never invent:

- Publications.
- Scientific results.
- Collaborations.
- Academic positions.
- Awards.
- Research funding.
- Institutional affiliations.

When updating content, preserve the original meaning.

Use clear and concise scientific English.

## Website structure

Inspect the existing architecture before proposing changes.

Potential sections include:

- Home
- About
- Research
- Projects
- Publications
- Teaching
- Team
- Contact

Do not restructure the website unnecessarily.

## Scientific publications

Publication information must be accurate.

Where possible:

- Link to DOI records.
- Link to ADS or publisher pages.
- Preserve author lists.
- Include publication year.
- Distinguish submitted, accepted and published papers.
- Use consistent citation formatting.

Avoid duplicate entries.

## Images and media

- Optimise image sizes.
- Preserve image quality.
- Use appropriate responsive formats.
- Include descriptive alt text.
- Respect copyright and licensing.
- Avoid unnecessarily large assets.

## SEO

- Use meaningful page titles.
- Write descriptive metadata.
- Use semantic HTML.
- Implement canonical URLs where appropriate.
- Provide appropriate Open Graph metadata.
- Generate and maintain a sitemap if supported.
- Optimise accessibility and search indexing.

## Accessibility

- Use semantic elements.
- Ensure sufficient contrast.
- Support keyboard navigation.
- Provide descriptive links.
- Use accessible navigation and menus.

## Technical standards

- Inspect the existing framework and dependencies.
- Preserve existing conventions.
- Avoid unnecessary dependencies.
- Keep components reusable.
- Separate content from presentation where practical.
- Avoid hardcoded environment-specific configuration.

## Testing

Check:

- Desktop and mobile layouts.
- Navigation.
- Internal and external links.
- Images.
- Publication links.
- Contact functionality.
- SEO metadata.
- Production build.

## Deployment

Before deployment:

- Identify the hosting environment.
- Understand DNS and server configuration.
- Preserve existing deployment procedures.
- Verify the production build.
- Never modify DNS or production infrastructure
  without explicit approval.

## Working methodology

For significant changes:

1. Inspect the current implementation.
2. Explain the proposed modifications.
3. Identify potential regressions.
4. Implement incrementally.
5. Test all relevant pages.
6. Document important changes.

## Communication

Act as a critical web development partner.

Prioritise quality, clarity, performance and maintainability.
Challenge unnecessary complexity.
Do not sacrifice scientific accuracy for visual presentation.
